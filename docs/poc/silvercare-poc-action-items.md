## PoC 핵심 목표

### Phase 0 — 범위 확정 (착수 전 필수)

**PoC 보드의 목표를 딱 한 줄로 결정해야 한다.**

"심정지 감지 알고리즘 검증"인지, "LTE-M 통신 및 통보 파이프라인 검증"인지, "배터리 수명 검증"인지에 따라 보드 형태가 완전히 달라진다. 셋 다 하나의 보드로 하려 하면 PoC 기간이 3배로 늘어난다.

> **권장**: 1차 PoC는 센서+알고리즘 / 2차 PoC는 통신+통보로 분리

| # | 결정 항목 | 비고 |
|---|-----------|------|
| P0-1 | PoC 범위를 한 줄로 작성하고 팀 합의 | 문서화 후 변경 금지 |
| P0-2 | 1차/2차 PoC 분리 여부 결정 | 일정·예산 영향 |
| P0-3 | 상용 평가 보드 조합 vs 커스텀 PCB 결정 | 시간 vs 완성도 트레이드오프 |

---

### Phase 1 — 센서 및 신호 품질 검증

> **사업 자체의 존폐를 결정하는 실측 단계.**  
> AI 에이전트가 생성한 알고리즘 초안은 이 단계에서 의미가 없다.

| # | 작업 | 판단 기준 |
|---|------|-----------|
| P1-1 | MAX86141 PPG 신호 실측 | 손목 착용 조건에서 raw PPG 파형 캡처. 노이즈 레벨, 모션 아티팩트 크기를 직접 확인 |
| P1-2 | 정상 맥파 vs 맥파 소실 구분 임계값 결정 | 실제 사람 손목에서 센서를 탈착하며 경계값을 반복 측정하여 확정. 시뮬레이션 불가 |
| P1-3 | LSM6DSO IMU 낙상·무움직임 임계값 결정 | 시니어 일상 동작(천천히 앉기, 몸 뒤척임)과 실제 낙상을 구분하는 가속도 임계값 직접 측정 |
| P1-4 | PPG + IMU 타임스탬프 동기화 확인 | 두 센서의 샘플링 클럭 드리프트 실측. 동기화 로직 확정 |

> **이 단계의 판단 기준**: "손목 PPG로 맥파 소실을 신뢰할 수 있게 잡을 수 있는가?"  
> 논문 수치(민감도 78.6%)가 우리 하드웨어에도 재현되는지는 직접 확인해야 한다.

---

### Phase 2 — 3중 검증 알고리즘 튜닝

| # | 작업 | 판단 기준 |
|---|------|-----------|
| P2-1 | 오신고 vs 미감지 트레이드오프 결정 | 임계값 낮추면 오신고↑, 높이면 미감지↑. 균형점은 사업 책임자와 개발자가 수치를 보며 직접 결정. AI 대신 결정 불가 |
| P2-2 | 90초 카운트다운 UX 검증 | 65세 이상 시니어 5~10명에게 착용시켜 "경보가 울렸을 때 취소 버튼을 찾아 누를 수 있는가" 직접 관찰. 버튼 위치·진동 패턴·표시 문구 이 단계에서 확정 |
| P2-3 | 엣지 케이스 목록 수동 작성 | 수면 중 센서 들뜸, 운동 중 격렬한 모션, 샤워 중 물 접촉 등 오신고 유발 시나리오를 개발자가 직접 목록으로 작성하고 각 대응 로직 확정 |

---

### Phase 3 — LTE-M 통신 검증

| # | 작업 | 판단 기준 |
|---|------|-----------|
| P3-1 | BG95 실망 환경 테스트 | 지하·엘리베이터·건물 내부에서 LTE-M attach 성공률 실측 |
| P3-2 | SMS 자동 발신 수신 형태 확인 | Cat-M1은 음성 미지원. SMS가 119 측에 어떤 형태로 수신되는지 통신사 담당자와 직접 확인 |
| P3-3 | PSM/eDRX 파라미터 결정 | 배터리 수명과 응급 감지 응답속도 트레이드오프를 실측값 기반으로 확정. 이론 계산과 실측값 불일치 시 실측 우선 |
| P3-4 | SMS 발신 지연 측정 | 경보 발생부터 SMS 수신까지 실제 지연 시간 측정. 목표: **95초 이내** |

### Phase 4 — 전력 예산 검증

| # | 작업 | 판단 기준 |
|---|------|-----------|

| P4-2 | 7일 배터리 목표 현실 검증 | 측정값 기반 실제 지속 시간 계산. 목표 미달 시 PPG 샘플링 주기 조정(예: 5분 주기)으로 어느 수준에서 7일이 가능한지 직접 확정 |

## 📋 전체 체크포인트 요약

```
Phase 0  PoC 목표 범위 확정          → 개발자 결정 필수
Phase 1  PPG/IMU 신호 실측           → 개발자 직접 측정
Phase 2  알고리즘 임계값 튜닝         → 개발자 + 사업책임자 공동 결정
Phase 3  LTE-M 통신 검증             → 개발자 실측
Phase 4  전력 예산 실측               → 개발자 실측
Phase 5  End-to-End 완주             → 개발자 직접 확인

위 각 단계의 사전 조사·코드 초안·BOM 초안
  → AI 에이전트 위임 가능 (섹션 A~E)
```

## ⚠️ PoC에서 가장 자주 실패하는 지점

**PPG 신호 품질이 기대 이하일 가능성이 높다.**

논문은 특정 하드웨어 플랫폼에서 나온 결과이고, MAX86141 + 손목 밴드 조합의 실제 SNR은 착용 압력·피부색·동작에 따라 크게 달라진다. Phase 1에서 이것이 확인되지 않으면 이후 모든 작업이 모래 위에 쌓이는 구조가 된다.

> **Phase 1에 PoC 전체 일정의 절반 이상 시간을 배정할 것을 권장한다.**
